AI 层：模型路由器 & Worker 设计
AIProvider 统一接口
interface AIProvider {
  analyzeImage(url, prompt, opts)
    // → GLM-5V 默认
  generateText(prompt, ctx, opts)
    // → DeepSeek 默认
  generateEmbedding(text)
    // → 用于 pgvector RAG
}
系统设置页绑定每个接口的模型+API Key
单例 providerRegistry，运行时可热切换
ImageAnalysisWorker
触发：作业上传后
输入：file_url, mode
调用：GLM-5V
输出：题目区域 · 学生答案
        批阅痕迹 · bbox · 置信度
写表：TeacherMark, GradingResult
GradingWorker
触发：ImageAnalysis 完成后
输入：题目+学生答案+标准答案
调用：DeepSeek
输出：建议分 · 错因类型
        知识点匹配 · 置信度
写表：GradingResult(更新)
QuestionGenWorker
触发：教师点击生成试题
输入：学生薄弱点 · 参数
调用：DeepSeek
输出：题目 · 答案 · 解析
        错因预判 · 命题意图
写表：Question(草稿)
MasteryUpdateWorker
触发：教师确认批阅后
输入：submissionId
逻辑：加权计算掌握度
        （难度·分值·错因·趋势）
写表：StudentMastery(upsert)
触发：ReportGenWorker
置信度机制
≥ 85%：自动展示，绿色标记
70–84%：展示但橙色提示「建议确认」
< 70%：红色标记「需要复核」，阻断自动入库

GLM-5V 返回结构化 JSON：
{ question_no, mark_type, score, text,
  bbox, confidence, reasoning }
三种批阅模式的处理链对比
模式①：未批阅 AI 批改
上传
→ ImageAnalysisWorker
   GLM-5V 识别题目+答案
→ GradingWorker
   DeepSeek 判分+错因
→ 前端展示 AI 建议分
→ 教师修改并确认
→ MasteryUpdateWorker
模式②：已批阅痕迹识别
上传
→ ImageAnalysisWorker
   GLM-5V 识别三层：
   原题/学生答案/批阅层
   提取 ✓ ✗ 扣分 评语
→ GradingWorker
   知识点匹配+错因分析
→ 前端展示识别结果
→ 教师确认
→ MasteryUpdateWorker
模式③：已批阅 + AI 复核
上传
→ ImageAnalysisWorker（同②）
   识别教师批阅结果
→ ReviewWorker（并行）
   DeepSeek 独立判分
→ 对比两份结果
   标记疑似不一致题目
→ 前端展示复核建议
   「疑似需确认」措辞
→ 教师逐项确认
→ MasteryUpdateWorker
