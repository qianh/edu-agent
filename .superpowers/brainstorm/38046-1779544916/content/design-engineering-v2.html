设计方案 §5（更新）：错误处理 · 测试策略 · 工程规范

去掉 Docker，本地直装依赖，生产直接部署

错误处理策略（不变）
AI API 调用失败
BullMQ 自动重试：3 次，指数退避 5s/30s/2min
GLM-5V 超时限制：60s per 请求
全失败 → job.status = "failed"，SSE 推送通知
低置信度
<70% → 标记 needs_review，阻断画像更新
70–84% → 橙色提示「建议确认」
≥85% → 绿色，可直接批量确认
API 错误响应
{ error: { code, message, details? } }
400 VALIDATION_ERROR
403 FORBIDDEN
422 AI_PARSE_ERROR
503 AI_UNAVAILABLE
测试策略（不变）
① 单元测试（Vitest）
掌握度计算 · 置信度分档 · 模型路由逻辑
纯函数，零 AI 依赖
② 集成测试（Vitest + 本地测试 DB）
API Routes + Prisma，连本地 PostgreSQL 测试库
Worker 用 mock provider 替代真实 AI
③ E2E（Playwright）
3 条主流程：上传AI批改 · 批阅识别 · 试题生成
AI 质量验收（离线脚本）
20 份标注样本 · 痕迹识别 ≥85% · 扣分 ≥90%
不达标调 prompt，不改架构
工程规范：本地直装 + 直接部署（无 Docker）
开发环境前置依赖（直装）
PostgreSQL 16
macOS: brew install postgresql@16
Windows: 官网安装包
启用 pgvector: CREATE EXTENSION vector;
Redis 7
macOS: brew install redis
Windows: Redis for Windows / WSL
启动: redis-server
文件存储
MVP 阶段：本地文件系统（./uploads/）
生产阶段：配置阿里云 OSS / 腾讯云 COS
STORAGE_TYPE=local | oss | cos
开发启动 & 生产部署
# 开发启动
pnpm install
pnpm prisma migrate dev
pnpm prisma db seed

# 终端 1
pnpm dev      # Next.js :3000
# 终端 2
pnpm worker  # BullMQ Worker

# 生产部署（Linux 服务器）
pnpm build
pm2 start ecosystem.config.js
# pm2 管理两个进程：
# next start (port 3000)
# node worker/index.js

# Nginx 反代 :3000
# SSL 用 certbot / 自签证书
pm2 ecosystem.config.js 管理两个进程
web: next start
worker: node lib/queue/worker-entry.js
PostgreSQL + Redis 作为系统服务运行
文件存储策略（MVP → 生产升级路径）
MVP 阶段：STORAGE_TYPE=local，文件存 ./uploads/，Next.js 静态路由直接提供服务
生产阶段：改 STORAGE_TYPE=oss，填入 OSS 配置，上传逻辑不变，只切存储层
