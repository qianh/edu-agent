## Context

edu-agent 是一个 Next.js 15 单体应用（前端页面 + API route + BullMQ worker + Prisma/Postgres + Redis 同仓共存，无独立后端服务/跨仓依赖）。"个性化试题生成"页面（`questions/generate/page.tsx`）现状：题型只能单选一种、统一设一个数量，知识点教师手动多选，worker（`question-gen.ts`）一次性调用 `deepseek.generateText` 生成整批 JSON 后落库，没有按学生学情自动出题、不支持图表题。

AI provider 现状（`lib/ai/registry.ts`）：仅有文本生成（`deepseek`）和图像理解（`glm5v.analyzeImage`，看图生文），**没有文生图能力**。`StudentMastery.masteryScore` 已是现成字段，学生详情页已用 `masteryScore < 60` 判定薄弱知识点，本次复用同一口径。`package.json` 已有 `recharts` 依赖，可直接复用做数据图表渲染。

本次目标是让试卷质量接近真实学校考试，覆盖几何图形、物理/化学/生物实验图等图表题，且要明确这些图表题的生成方案选型。

## Goals / Non-Goals

**Goals**:
- 题型（单选/填空/解答）各自独立设置数量
- 按学生 `StudentMastery` 自动 90/10（薄弱/良好）知识点分层抽样出题，教师可选手动收窄知识点范围（权重逻辑不变）
- 图表题按百分比 + "至少 1 道"下限配额分配
- 几何图形/数据图表用结构化参数渲染，保证图文一致；出题流程改为"按题型分大纲 → 逐题生成润色 → 逐题校验"，单题失败可独立重试/跳过
- `Question` 模型新增字段支持图表题展示

**Non-Goals**:
- 不引入文生图第三方 provider
- 实验图（物理电路图/化学装置图/生物结构图）本次只产出文字提示词，不真实渲染
- 不对历史 `Question` 数据做回填迁移
- 不改变现有 `审核通过入库`（approve）流程

## Decisions

### D1: 图表题按图形类型分两种生成路径，不统一走文生图

**选择**：几何图形 + 数据图表 → LLM 产出结构化参数 `chartSpec`（JSON），前端用代码渲染（几何用新增的轻量 SVG 渲染组件，数据图复用 `recharts`）。实验图 → 只产出 `chartImagePrompt` 文字提示词，不渲染。

**理由**：结构化参数与题干/答案同源生成，渲染结果天然与题目一致，不需要额外的"图文一致性"AI 校验环节（用代码渲染就是校验本身）。实验图形态高度多样（电路元件组合、装置形态），无法用统一的小型结构化 schema 覆盖，引入文生图又会带来新的不可验证风险（生成图的内容是否真的匹配题目，目前没有可靠的自动校验手段）。

**备选方案**：统一走文生图（GLM 或其他文生图 API）。否决原因：现状无 provider，新增第三方依赖+成本，且生成图的图文一致性无法在 v1 自动校验，风险与工作量都更高，不符合本次"先把能做扎实的部分做扎实"的范围。

### D2: 知识点抽样候选池与不足处理

**选择**：候选池 = 该学生在所选学科/年级下有 `StudentMastery` 记录的知识点（教师手选范围内时进一步收窄）。薄弱点不足覆盖题量时，允许同一薄弱知识点被多道题重复使用，不借用良好知识点池；该学生完全没有薄弱知识点时，才整体降级为全部从良好知识点出题，并在任务结果中提示。

**理由**：保持"90% 聚焦薄弱点"这个核心诉求不被稀释；只有在物理上不可能满足时才降级，且降级要可见，不能静默发生。

**备选方案**：不足时混合借用良好知识点凑数。否决原因：会让"按学情精准补弱"的核心价值打折，且教师不会知道发生了降级。

### D3: 图表题配额算法

**选择**：每种题型独立计算：`count_type = 0` 不强制；否则 `chart_count = max(1, round(count_type × P / 100))`，封顶 `count_type`。

**理由**：直接贴合用户原话"一旦勾选图表题，每种题型至少一道"——这个下限与百分比数值无关，百分比只决定超过 1 道之后还要不要再加。

### D4: 两阶段生成 —— 大纲（按题型分别生成）→ 逐题生成 + 校验

**选择**：阶段一对每种题型分别调用一次 LLM 生成该题型的大纲（草稿题干+答案，图表题额外派生 `chartSpec`/`chartImagePrompt`），失败整体重试 ≤2 次；阶段二严格按大纲逐题调用 LLM 把草稿"润色/完整化"为正式题目，并校验是否偏离大纲（题干主旨/答案结论/图表一致性），单题失败重试 ≤2 次，最终仍失败则跳过该题（不拖累整批），任务结果记录"成功 X/Y 题"。

**理由**：把"一次性生成整批 JSON 失败就全部重来"的脆弱模式，换成"按题型隔离失败域 + 逐题隔离失败域"，单点失败不影响整体产出；大纲先行也保证后续逐题生成不会偏题。

**备选方案**：维持现状一次性生成整批。否决原因：现有线上行为已暴露"批量 JSON 解析失败即全盘失败"的脆弱性，且无法支撑图表题这种需要额外结构化产出的场景。

### D5: 数据模型扩展为可选字段，零迁移成本

**选择**：`Question` 新增 `isChart Boolean @default(false)`、`chartSpec Json?`、`chartImagePrompt String?`。

**理由**：全部可选/带默认值，`prisma migrate dev` 只新增列，不改变既有行的值，老数据自动满足新 schema，无需回填脚本。

### D6: 前端表单的学生/知识点字段交互

**选择**："学生"下拉必选，驱动 90/10 抽样；"知识点"多选改为可选——不选用自动抽样，选了则在选中范围内仍按 90/10 权重分配（不是均匀分配）。

**理由**：保留教师原有"手动选知识点"的使用习惯，同时让"按学情出题"成为默认行为而不是要额外开关；手选时延续 90/10 权重，避免出现"选了知识点反而权重逻辑整体失效"的不一致体验。

## Risks / Trade-offs

- **图表题渲染覆盖面有限**（几何图形的 SVG 渲染器需要覆盖常见图形：三角形/四边形/圆/坐标系/数轴等，复杂或非常规几何图形可能渲染失真）→ 缓解：渲染器按"先支持初中数学常见图形集合，渲染失败时降级为纯文字提示词"处理，不强求100%覆盖率。
- **逐题生成阶段引入更多 LLM 调用次数**（按题型出大纲 + 逐题生成，调用次数从 1 次变为 N+M 次）→ 缓解：单题失败重试上限 2 次，避免无限重试导致任务耗时不可控；后续可观察实际任务耗时再决定是否要加并发。
- **学生无薄弱知识点时的降级**可能被教师误解为"系统出错"→ 缓解：任务结果中显式提示"该生暂无薄弱知识点，已从已掌握知识点出题"。
- **风险评级为 H**（按用户拍板，基于真实实现难度而非表面模块数）→ 缓解：N3 进入对抗审查模式、N5 用 TDD 流程自律执行（用户已确认不安装 TDD Guard 工具，无自动化硬约束，需要执行阶段额外自觉）、N7 审查 + 合并前需 Human Approval。

## Migration Plan

1. `prisma/schema.prisma` 新增 `Question.isChart`/`chartSpec`/`chartImagePrompt` 三个可选字段
2. `pnpm prisma migrate dev --name add_question_chart_fields` 生成迁移（新增列，不删不改现有列）
3. 实现表单/API/worker 变更（见 tasks.md）
4. 本地验证：`pnpm lint && pnpm typecheck && pnpm build && pnpm test`
5. 手动验证完整出题流程（见 tasks.md 验证章节）
6. 回滚方案：若需回滚，`prisma migrate resolve` 回退该迁移（新增列回滚不影响其他数据），并 `git revert` 相关提交
